# 度小满数据生成说明

## 一、概述

度小满测试/报送数据分为两条业务线，二者**取数与加工的整体逻辑完全一致**，仅在**产品编码、年利率、对账日期、取数范围**等参数上存在差异：

| 业务线 | 代码包 | 产品编码 | 年利率 | 对账（回款）月份 |
|--------|--------|----------|--------|------------------|
| 正堂-度小满 | `modules/dxm` | `DXM` | 0.24 | 2026-04 |
| 昌泰-度小满 | `modules/ctdxm` | `CTDXMXYXJ` | 0.18 | 2026-02 ~ 2026-03 |

数据来源与加工方式统一为：**从生产库取数 → 导入本地库 → 本地 SQL 加工 → 程序生成还款计划与还款明细**。

> **正堂与昌泰取数方式的区别**：
> - **正堂**：每次按需从生产库取数（执行第二节取数 SQL），再导入本地加工。
> - **昌泰**：本地库已沉淀了大量历史数据，**无需每次去生产取数**，直接在本地按 `id` **区间**（如 `id >= 76500 and id < 81000`）圈定本批要加工的数据即可。

整体链路：

```
生产库
  │  ① 取数 SQL（按身份证地址/产品码筛选"涉农"客户，分页 limit 截取）
  ▼
本地库（apply_base_info 进件 + ln_loan_info 放款）
  │  ② SQL 加工（统一产品码、渠道、利率、对账日、借据号、到期日）
  ▼
ln_loan_info / apply_base_info 加工完成
  │  ③ GeneratePlan.test()  等额本息生成还款计划 → ln_plan_info
  ▼
ln_plan_info
  │  ④ GenerateDetail.GenerateDetail()  按还款计划生成还款明细 → ln_repay_info
  ▼
ln_repay_info（最终报送数据）
  │  ⑤ 校验 SQL（金额、笔数、借据号、本金之和一致性核对）
```

## 二、第一步：生产取数

### 2.1 取数目的

从生产库 `apply_base_info`（进件）中筛选出符合"涉农"特征的客户，关联 `ln_loan_info`（放款）后导出到本地库。

### 2.2 筛选规则

1. **地址必须包含"涉农"特征词**：`乡` / `村` / `组` / `号` / `庄` / `屯` / `寨`（满足任一即可）。
2. **地址必须排除"城镇/非农"特征词**：如 `社区`、`小区`、`广场`、`单元`、`层`、`室`、`公司`、`大厦`、`栋`、`座`、`幢`、`宿舍`、`大院`、`巷`、`新区`、`机关`、`家属院`、`非农` 等，以及各类"路 X 号""街 X 号"的城市门牌格式。
3. **排除特定省份**：海南、新疆、西藏、安徽、吉林。
4. **排除特定身份证归属地前两位**：`46`（海南）、`65`（新疆）、`54`（西藏）、`34`（安徽）、`22`（吉林）。
5. **限定产品编码** `product_no IN (...)`：覆盖中保、樽昊、富宸、鼎丰、正堂、昌泰、大有等一批产品码（详见取数 SQL 清单）。
6. **分页截取**：`order by id limit 起始,数量`，按需分批取数（如 `limit 354000,20000`）。
7. **必须有对应放款记录**：`left join ln_loan_info b on a.apply_no=b.apply_no where b.id is not null`。

> 取数 SQL 外层一般用 `select sum(a.loan_amt)` / `count` 先核对将要导出的金额与笔数规模，再正式导出明细。

## 三、第二步：本地 SQL 加工（进件 + 放款）

将取数得到的 `apply_base_info`、`ln_loan_info` 导入本地库后，按以下顺序执行加工 SQL（以**正堂**为例，昌泰除产品码/利率/日期外步骤相同）。

### 步骤 1：校验借据号与 ID 是否一致

```sql
select * from apply_base_info a
left join ln_loan_info b on a.id = b.id
where a.apply_no != b.apply_no;
```
确认进件与放款两表通过 `id` 关联时借据号是否对应，无结果即正常。

### 步骤 2：统一产品编码

```sql
update ln_loan_info  set product_no = 'DXM';
update apply_base_info set product_no = 'DXM';
```

### 步骤 3：加工进件基础信息

```sql
update apply_base_info set
    partner_no='DXM', product_no='DXM', product_name='度小满',
    apply_time=recon_date, apply_status='01',
    cfund_channel_no='ZT-DMX-NBTS', cfund_channel_name='正堂-度小满-宁波通商',
    repay_way='01', year_rate='0.24',
    compensate_days=0, grace_day=0, interest_free_period=0, loan_use='07';
```
统一渠道、还款方式（01 等额本息）、年化（0.24）、宽限期/免息期等。

### 步骤 4：加工对账日期

两种方式二选一：

```sql
-- 方式A：保留原始日号，统一归到 2026-04（超过 30 号的归到 30 号）
update apply_base_info set recon_date =
    STR_TO_DATE(CONCAT('2026-04-', if(DAY(recon_date)>30,30,DAY(recon_date))), '%Y-%m-%d');

-- 方式B：在 2026-04 内随机分布
update apply_base_info set recon_date =
    DATE_ADD('2026-04-01', INTERVAL FLOOR(RAND() * 30) DAY);
```

### 步骤 5：生成借据号

```sql
update apply_base_info set
    apply_no = concat('DXM', recon_date, '_', LPAD(ID, 8, '0')),
    apply_time = recon_date;
```
借据号规则：`DXM` + 对账日期 + `_` + 8 位补零的主键 ID。

### 步骤 6：回写放款表的对账日期与借据号

```sql
update ln_loan_info a
left join apply_base_info b on a.id = b.id
set a.recon_date = b.recon_date, a.apply_no = b.apply_no;
```

### 步骤 7：加工放款基础信息

```sql
update ln_loan_info set
    loan_time=recon_date, total_term=12,
    loan_month=date_format(recon_date,'%Y-%m'),
    loan_status='NOR', loan_req_no=apply_no, product_no='DXM';
```
统一放款时间=对账日、总期数=12、贷款状态正常（NOR）等。

### 步骤 8：计算到期日

```sql
update ln_loan_info set due_date = date_add(recon_date, INTERVAL total_term MONTH);
```

### 步骤 9：加工后一致性校验

```sql
-- 借据号 / 对账日 / 金额是否匹配
select * from apply_base_info a left join ln_loan_info b on a.id=b.id
where a.apply_no!=b.apply_no or a.recon_date!=b.recon_date or a.loan_amt!=b.loan_amt;

-- 身份证是否匹配
select * from apply_base_info a left join ln_loan_info b on a.id=b.id
where a.id_card != b.id_card;

-- 总金额、笔数核对
select sum(loan_amt),count(0) from apply_base_info;
select sum(loan_amt),count(0) from ln_loan_info;
```

## 三-补充、昌泰本地 SQL 加工（按 ID 区间）

昌泰本地已有大量历史数据，**不再从生产取数**，每次只需按 `id` 区间圈定本批数据加工。下面是昌泰一批次的加工 SQL（与正堂对应步骤一致，差异在产品码、渠道、对账月、`id` 范围、新增 `repay_day`）。

### 1. 统一产品码与进件基础信息

```sql
update apply_base_info set
    partner_no='CTDXM', product_no='CTDXMXYXJ', product_name='昌泰-度小满-兴业消金',
    apply_time=recon_date, apply_status='01',
    cfund_channel_no='CT-DXM-XYXJ', cfund_channel_name='昌泰-度小满-兴业消金'
where 1=1;

update ln_loan_info set product_no='CTDXMXYXJ' where 1=1;
```

### 2. 圈定并核对本批 ID 区间

```sql
-- 可用变量记录起止 id（按需调整）
set @startId = '46000';
set @endId   = '56000';

-- 核对本批金额与笔数（本例区间 [76500, 81000)）
select sum(loan_amt), count(0) from apply_base_info where id>=76500 and id<81000;
select sum(loan_amt), count(0) from ln_loan_info  where id>=76500 and id<81000;
```

> 所有后续加工 SQL 均带 `where id>=76500 and id<81000` 限定本批，**避免影响已加工过的历史数据**。

### 3. 加工对账日期（归到 2026-03）

```sql
update apply_base_info set recon_date =
    STR_TO_DATE(CONCAT('2026-03-', if(DAY(recon_date)>31,31,DAY(recon_date))), '%Y-%m-%d')
where id>=76500 and id<81000;
```

### 4. 生成借据号（前缀 CTDXM）

```sql
update apply_base_info set
    apply_no = concat('CTDXM', recon_date, '_', LPAD(ID, 8, '0')),
    apply_time = recon_date
where id>=76500 and id<81000;
```

### 5. 回写放款表对账日与借据号

```sql
update ln_loan_info abi inner join apply_base_info lli on abi.id = lli.id
set abi.recon_date = lli.recon_date, abi.apply_no = lli.apply_no
where lli.id>=76500 and lli.id<81000;
```

### 6. 加工放款基础信息（含 repay_day）

```sql
update ln_loan_info set
    loan_time = recon_date,
    due_date  = date_add(recon_date, INTERVAL total_term MONTH),
    loan_month= date_format(recon_date,'%Y-%m'),
    loan_status='NOR',
    repay_day = date_format(recon_date,'%d')
where id>=76500 and id<81000;
```

> 与正堂相比，昌泰这步**多设置了 `repay_day`（还款日 = 对账日的日号）**，且到期日 `due_date` 在同一条 SQL 里一并计算。

### 7. 加工后一致性校验

```sql
select * from apply_base_info a left join ln_loan_info b on a.id = b.id
where a.apply_no!=b.apply_no or a.recon_date!=b.recon_date or a.loan_amt!=b.loan_amt;
```

> 加工完成后，同样运行 `ctdxm/GeneratePlan.test()`（利率 0.18、`getLoanInfoById("76500","81000")`）生成还款计划，再运行 `ctdxm/GenerateDetail`（产品码 `CTDXMXYXJ`、回款区间 `20260201~20260331`）生成还款明细，最后执行第六节核对 SQL。

## 四、第三步：生成还款计划（GeneratePlan）

> 正堂：`modules/dxm/GeneratePlan.java`；昌泰：`modules/ctdxm/GeneratePlan.java`

### 4.1 作用

读取加工完成的 `ln_loan_info`，按 **等额本息（自然月）** 算法逐笔生成还款计划，写入 `ln_plan_info`。

### 4.2 核心算法 `calculation_DEBX_ZRY`

- 月利率 = 年利率 / 12。
- 每月还款额（本息）= `本金 × 月利率 × (1+月利率)^期数 ÷ [(1+月利率)^期数 - 1]`。
- 每期：`月还利息 = 剩余本金 × 月利率`；`月还本金 = 月还本息 - 月还利息`。
- **最后一期**：`利息 = 月还本息 - 剩余本金`，避免精度误差；若利息 ≤ 0 则兜底为 `0.1` 元，避免出现负利息。
- 回款日期：以放款日逐月 `+1 个月`（自然月，回款日与出借日同号）。
- 每期落库字段：`term`、`repay_total_amt`、`int_amt`、`print`（本金）、`recon_date`/`repay_date`、`product_no`、`apply_no`、`status='NOR'`、`ovd_days=0`。

### 4.3 入口 `test()` —— 正堂与昌泰差异点

| 项 | 正堂(dxm) | 昌泰(ctdxm) |
|----|-----------|-------------|
| 年利率 yearRate | `0.24` | `0.18` |
| 取数方法 | `getLoanInfoByYear("0")`（`id > 0` 全量） | `getLoanInfoById("76500","81000")`（`id` 在 [76500, 81000) 区间） |
| 落库产品码 | `DXM` | `CTDXMXYXJ` |

```java
// 正堂
BigDecimal yearRate = BigDecimal.valueOf(0.24);
List<LnLoanInfo> list = lnLoanInfoMapper.getLoanInfoByYear("0");

// 昌泰
BigDecimal yearRate = BigDecimal.valueOf(0.18);
List<LnLoanInfo> list = lnLoanInfoMapper.getLoanInfoById("76500", "81000");
```

> 对应 Mapper：`getLoanInfoByYear` → `select * from ln_loan_info where id > #{id}`；`getLoanInfoById` → `select * from ln_loan_info where id >= #{startId} and id < #{id}`。

## 五、第四步：生成还款明细（GenerateDetail）

> 正堂：`modules/dxm/GenerateDetail.java`；昌泰：`modules/ctdxm/GenerateDetail.java`

### 5.1 作用

按指定回款日期区间，遍历 `ln_plan_info` 中**未结清（status != 'FP'）**的还款计划，生成对应的还款明细 `ln_repay_info`（即"已还/实还"明细）。

### 5.2 逻辑

- 分页查询 `selectAllLimit(id, batchSelectSize, reconDate, endDate)`：
  `where id > #{id} and status != 'FP' and repay_date between #{reconDate} and #{endDate} order by id limit #{batchSelectSize}`。
- 逐条将计划映射为还款明细：
  - `tran_rp_no = apply_no + "_" + term`（流水号）
  - `recon_date / repay_time = 计划的 repay_date`
  - `print / int_amt / repay_total_amt` 沿用计划值
  - `repay_type = '1'`
- 批量 `insertOrUpdateBatchRepayInfo` 落库，以本批最大 `id` 作为下一批起点，循环直到无数据。

### 5.3 正堂与昌泰差异点

| 项 | 正堂(dxm) | 昌泰(ctdxm) |
|----|-----------|-------------|
| 产品码 productNo | `DXM` | `CTDXMXYXJ` |
| 回款日期区间 reconDate~endDate | `20260401` ~ `20260430` | `20260201` ~ `20260331` |

## 六、第五步：最终核对 SQL

```sql
-- 进件金额 vs 放款合同/放款金额 vs 还款计划本金之和 vs 还款明细本金之和
select a.recon_date 对账日期, substr(a.apply_no,5) 截取借据号, a.apply_no 借款申请编号,
       a.loan_amt '进件-借款金额', b.contract_amt '放款-合同金额', b.loan_amt '放款-放款金额',
       c.act_print '还款计划应还本金之和', d.act_print '还款明细本金之和'
from apply_base_info a
left join ln_loan_info b on a.apply_no=b.apply_no
left join (select sum(print) act_print, apply_no from ln_plan_info  group by apply_no) c on a.apply_no=c.apply_no
left join (select sum(print) act_print, apply_no from ln_repay_info group by apply_no) d on a.apply_no=d.apply_no
where a.loan_amt!=b.loan_amt or a.loan_amt!=c.act_print or b.loan_amt!=c.act_print or c.apply_no is null
group by a.recon_date;

-- 当月应还本金核对（计划 vs 明细 应一致）
select sum(print) from ln_plan_info  where repay_date between '2026-04-01' and '2026-04-30' and status='NOR';
select sum(print) from ln_repay_info where id > 227681471;

-- 历史已结清（FP）月份本金核对
select sum(act_print) from ln_plan_info where repay_date between '2025-09-01' and '2025-09-30' and status='FP';
```

校验通过标准：进件借款金额 = 放款金额 = 还款计划本金之和 = 还款明细本金之和，且笔数一致。

## 七、执行顺序速查

1. 生产执行**取数 SQL**，核对金额/笔数后导出明细 → 导入本地。
2. 本地按 **步骤 1~9** 执行加工 SQL（注意区分正堂/昌泰的产品码、渠道、利率、对账月）。
3. 运行 `GeneratePlan.test()` 生成 `ln_plan_info`（确认 yearRate 与取数范围）。
4. 运行 `GenerateDetail.GenerateDetail()` 生成 `ln_repay_info`（确认产品码与回款日期区间）。
5. 执行**第六步核对 SQL**，确保四表金额、笔数一致。

## 八、正堂 vs 昌泰 参数差异汇总

| 参数 | 正堂(dxm) | 昌泰(ctdxm) |
|------|-----------|-------------|
| 数据来源 | 每次从生产取数后导入本地 | 本地已沉淀历史数据，按 `id` 区间圈定加工，不重复取数 |
| partner_no | `DXM` | `CTDXM` |
| 产品编码 product_no | `DXM` | `CTDXMXYXJ` |
| product_name | 度小满 | 昌泰-度小满-兴业消金 |
| 年利率 | 0.24 | 0.18 |
| 渠道编码/名称 | `ZT-DMX-NBTS` / 正堂-度小满-宁波通商 | `CT-DXM-XYXJ` / 昌泰-度小满-兴业消金 |
| 借据号前缀 | `DXM` | `CTDXM` |
| 对账/回款月份 | 2026-04 | 2026-03（回款明细区间含 2 月） |
| 加工范围限定 | 全量（取数已圈定） | `where id>=76500 and id<81000` 等 ID 区间 |
| repay_day | 未单独设置 | 设置为对账日的日号 |
| 生成计划取数 | `getLoanInfoByYear("0")` | `getLoanInfoById("76500","81000")` |
| GenerateDetail 区间 | 20260401~20260430 | 20260201~20260331 |
