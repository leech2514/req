# 23 DataWorks 数据建模

## 23.1 建模方式

### 规范建模（推荐）
- 通过 DataWorks 建模工具
- 自动生成 DDL
- 统一命名规范
- 与数据地图联动

### 自由建模
- 直接写 DDL
- 灵活但缺乏规范
- 适合探索阶段

## 23.2 数仓分层

```
┌─────────────────────────────────┐
│  ADS（应用数据层）              │
├─────────────────────────────────┤
│  DWS（汇总数据层）              │
├─────────────────────────────────┤
│  DWD（明细数据层）              │
├─────────────────────────────────┤
│  DIM（维度层）                  │
├─────────────────────────────────┤
│  ODS（操作数据层）              │
└─────────────────────────────────┘
```

### 各层职责
| 层 | 职责 | 数据特点 |
|----|------|---------|
| ODS | 原始数据入仓 | 与源头一致 |
| DWD | 清洗 + 维度退化 | 明细 + 维度 ID |
| DWS | 预聚合 | 按主题汇总 |
| ADS | 应用结果 | 直接出报表 |
| DIM | 维度表 | 缓慢变化维 |

## 23.3 维度建模

### 维度建模方法
- **星型模型**：1 事实表 + 多维度表
- **雪花模型**：维度表进一步规范化

### 事实表
- 包含度量值（金额、数量）
- 包含外键（指向维度）
- 粒度明确（一笔订单/一次点击）

### 维度表
- 描述性字段
- 缓慢变化维（SCD）
- 退化维度（并入事实表）

## 23.4 命名规范

### 表命名
| 层 | 规范 | 示例 |
|----|------|------|
| ODS | `ods_<来源>_<表名>_<增量/全量>_di/fi` | `ods_mysql_user_di` |
| DWD | `dwd_<数据域>_<业务过程>_<粒度>_di` | `dwd_trade_order_di` |
| DWS | `dws_<数据域>_<统计周期>_<主题>_df` | `dws_trade_user_1d_df` |
| ADS | `ads_<应用>_<业务>` | `ads_user_profile` |
| DIM | `dim_<主题>_<维度>_df` | `dim_user_info_df` |

### 字段命名
- 主键：`id`
- 外键：`<表名>_id`
- 金额：`amount` / `total_amount`
- 数量：`cnt` / `qty`
- 时间：`create_time` / `update_time`
- 标志：`is_xxx`
- 状态：`status`

### 后缀含义
- `_di`：日增量
- `_df`：日全量
- `_hi`：小时增量
- `_hf`：小时全量
- `_1d`：1 天汇总
- `_nd`：N 天汇总
- `_td`：截至当天累计

## 23.5 数据域划分

### 概念
- 按业务领域划分数据
- 便于管理与权限控制

### 示例
| 数据域 | 内容 |
|--------|------|
| 交易域 | 订单、支付、退款 |
| 用户域 | 注册、登录、画像 |
| 商品域 | 商品、SKU、类目 |
| 营销域 | 活动、优惠券 |
| 流量域 | PV、UV、点击 |

## 23.6 数据地图

### 功能
- 元数据检索
- 血缘关系
- 数据预览
- 资产统计

### 应用
- 找表：按名称/主题/负责人
- 看血缘：上下游影响分析
- 评估：表大小、分区数、热度

## 23.7 建模工具

### 操作流程
1. 创建数据域
2. 创建业务过程
3. 定义维度
4. 创建事实表
5. 创建汇总表
6. 生成 DDL

### 优势
- 规范化
- 可视化
- 与开发联动
