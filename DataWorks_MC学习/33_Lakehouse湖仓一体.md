# 33 Lakehouse 湖仓一体

## 33.1 湖仓一体概念

### 背景
- 数据仓库：结构化、高性能、成本高
- 数据湖：低成本、灵活、治理弱
- 湖仓一体：融合两者优势

### 特性
- 统一存储（OSS）
- 多引擎访问
- ACID 事务
- Schema 管理

## 33.2 阿里云湖仓架构

```
┌─────────────────────────────────────┐
│      计算引擎（MC/Flink/Spark）     │
├─────────────────────────────────────┤
│      元数据层（DLF）                │
├─────────────────────────────────────┤
│      存储层（OSS）                  │
└─────────────────────────────────────┘
```

### 组件
| 组件 | 作用 |
|------|------|
| OSS | 对象存储，海量低成本 |
| DLF | 数据湖构建，元数据 + 表格式 |
| MC | 通过外部表访问 OSS |
| Hologres | 交互式分析 |
| Flink | 实时写入 |

## 33.3 MaxCompute 外部表

### 创建外部表
```sql
CREATE EXTERNAL TABLE IF NOT EXISTS mc_external_table (
    id BIGINT,
    name STRING,
    create_time TIMESTAMP
)
STORED AS ORC
LOCATION 'oss://bucket/path/table/';
```

### 支持格式
- ORC
- Parquet
- CSV
- Avro
- TextFile

### 特点
- 不占用 MC 存储
- 不支持分区裁剪（部分场景）
- 适合低频查询
- 性能低于内部表

## 33.4 DLF 数据湖构建

### 功能
- 元数据管理
- 表格式（Iceberg/Hudi/Delta）
- 数据目录
- 权限管理

### 与 MC 集成
- MC 通过外部表访问 DLF 表
- DLF 提供 ACID 能力

## 33.5 湖仓一体应用场景

### 场景 1：冷数据归档
- 热数据在 MC 内部表
- 冷数据迁到 OSS（外部表）
- 降低存储成本

### 场景 2：多引擎共享
- 数据存 OSS
- MC/Flink/Spark 共享
- 避免数据搬迁

### 场景 3：流批一体
- Flink 实时写入 OSS（Iceberg）
- MC 离线查询
- 统一存储

## 33.6 MC 内部表 vs 外部表

| 维度 | 内部表 | 外部表 |
|------|--------|--------|
| 存储 | MC | OSS |
| 性能 | 高 | 中 |
| 成本 | 高 | 低 |
| 事务 | 支持 | 有限 |
| 分区 | 支持 | 部分支持 |
| 适用 | 高频查询 | 低频/归档 |

## 33.7 湖仓迁移策略

### 从纯数仓到湖仓
1. 评估冷热数据
2. 冷数据转外部表
3. 保留热数据内部表
4. 逐步迁移

### 注意事项
- 性能评估（外部表慢于内部表）
- 元数据一致性
- 权限模型变化
