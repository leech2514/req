# 14 MC 物化视图

## 14.1 概念

物化视图（Materialized View, MV）是 **预计算并存储** 的查询结果，用于：
- 加速查询（查询改写）
- 降低计算成本
- 替代部分汇总表

## 14.2 与普通视图区别

| 维度 | 普通视图 | 物化视图 |
|------|---------|---------|
| 存储 | 不存数据，仅存定义 | 存储数据 |
| 更新 | 实时 | 需刷新 |
| 查询改写 | 否 | 是（自动） |
| 性能 | 无提升 | 显著提升 |

## 14.3 创建物化视图

```sql
CREATE MATERIALIZED VIEW IF NOT EXISTS mv_user_order_stats
LIFECYCLE 30
AS
SELECT
    user_id,
    ds,
    COUNT(*) order_cnt,
    SUM(amount) total_amount
FROM orders
GROUP BY user_id, ds;
```

## 14.4 查询改写

当用户查询命中 MV 时，MC 自动改写：

```sql
-- 原始查询
SELECT user_id, SUM(amount) FROM orders WHERE ds='20260813' GROUP BY user_id;

-- 自动改写为
SELECT user_id, total_amount FROM mv_user_order_stats WHERE ds='20260813';
```

### 改写条件
- 聚合函数一致
- GROUP BY 字段一致
- 查询字段在 MV 中存在
- 分区条件在 MV 中可裁剪

## 14.5 刷新策略

### 手动刷新
```sql
ALTER MATERIALIZED VIEW mv_name REBUILD;
```

### 自动刷新
- 基表数据变化时自动触发
- 通过基表分区变更驱动

## 14.6 使用场景

- **高频聚合查询**：如日活、GMV
- **多维度汇总**：替代多个 DWS 表
- **历史趋势**：减少重复计算

## 14.7 注意事项

- MV 占用存储空间
- 刷新有成本，避免频繁刷新
- MV 不支持复杂 JOIN 改写（部分场景）
- MV 是只读的，不能直接写入
