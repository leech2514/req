# 31 性能优化最佳实践

## 31.1 SQL 优化

### 1. 分区裁剪
```sql
-- ✅ 正确
SELECT * FROM orders WHERE ds = '${bizdate}';

-- ❌ 错误（全表扫描）
SELECT * FROM orders;

-- ❌ 错误（函数导致失效）
SELECT * FROM orders WHERE SUBSTR(ds,1,6) = '202608';

-- ✅ 正确
SELECT * FROM orders WHERE ds >= '20260801' AND ds <= '20260831';
```

### 2. 字段选择
```sql
-- ✅ 只查必要字段
SELECT user_id, amount FROM orders;

-- ❌ 查询所有字段
SELECT * FROM orders;
```

### 3. JOIN 优化
```sql
-- 小表 JOIN 大表，使用 MAPJOIN
SELECT /*+ MAPJOIN(small_t) */ *
FROM big_table b
JOIN small_table s ON b.id = s.id;

-- 大表 JOIN 大表，分桶
-- 建表时 CLUSTERED BY (id) INTO N BUCKETS
```

### 4. 数据倾斜处理

#### 现象
- 某个 reducer 长时间运行
- 任务进度卡在 99%

#### 解决方案
```sql
-- 1. 数据采样定位倾斜 key
SELECT user_id, COUNT(*) cnt
FROM orders GROUP BY user_id ORDER BY cnt DESC LIMIT 10;

-- 2. 倾斜 key 单独处理
SELECT user_id, SUM(amount)
FROM orders
WHERE user_id != 0
GROUP BY user_id
UNION ALL
SELECT '0' user_id, SUM(amount)
FROM orders
WHERE user_id = 0;

-- 3. 加随机前缀打散
SELECT SPLIT_PART(skew_key,'_',2) k, SUM(v)
FROM (
    SELECT CONCAT(CAST(RAND() AS STRING),'_',skew_key) skew_key, v
    FROM skew_table
) t
GROUP BY SPLIT_PART(skew_key,'_',2);
```

### 5. 聚合优化
```sql
-- 先过滤再聚合
SELECT user_id, SUM(amount)
FROM (
    SELECT * FROM orders WHERE ds='${bizdate}' AND status=1
) t
GROUP BY user_id;
```

### 6. 避免笛卡尔积
```sql
-- ❌ 笛卡尔积
SELECT * FROM a, b;

-- ✅ 显式 JOIN 条件
SELECT * FROM a JOIN b ON a.id = b.id;
```

## 31.2 表设计优化

### 1. 分区设计
- 按查询习惯设计分区
- 日分区最常见
- 避免分区过多（单表 < 6 万）

### 2. 分桶设计
- 大表按 JOIN 字段分桶
- 桶数 = 数据量 / 100MB
- 一般 16/32/64

### 3. 物化视图
- 高频聚合查询
- 自动查询改写
- 注意刷新成本

### 4. 生命周期
- ODS：保留 1-3 年
- DWD：保留 2-5 年
- DWS：保留 1-3 年
- ADS：保留 3-12 月

## 31.3 资源优化

### 1. 资源组选择

### 2. 任务并发

### 3. 任务优先级
- 核心任务高优先级
- 非核心任务低优先级
- 配合基线

## 31.4 小文件治理

### 问题
- 小文件过多导致元数据压力
- 影响查询性能

### 解决
```sql
-- 合并小文件
ALTER TABLE table_name MERGE SMALLFILES;

-- 建表时设置参数
SET odps.sql.mapper.merge.small.size.avg=64;  -- MB
```
