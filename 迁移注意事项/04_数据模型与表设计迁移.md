# 04 数据模型与表设计迁移

## 4.1 分层架构对照

DMS/Xihe 与 DataWorks/MC 的数仓分层概念基本一致：
- ODS / DWD / DWS / ADS / DIM

差异点：
- DataWorks 推荐使用 **主题域 + 分层** 双维度管理
- DataWorks 提供 **数据地图、血缘、规范建模** 能力，建议启用

## 4.2 表设计差异

### 分区表
| 维度 | Xihe | MaxCompute |
|------|------|-----------|
| 分区字段声明 | 在表字段中 | **单独 PARTITIONED BY** |
| 多级分区 | 支持 | 支持（建议 ≤ 3 级） |
| 分区字段类型 | 任意 | 仅 STRING（旧）/ 多类型（新） |
| 分区数量上限 | 较宽松 | 单表 6 万个 |

**注意**：MC 分区字段 **不能** 出现在字段定义中，迁移时需调整 DDL。

### 生命周期
- Xihe：依赖外部存储策略
- MC：`LIFECYCLE n` 关键字，按分区自动回收
- 建议为 ODS/日志表统一配置 LIFECYCLE

### 物化视图
- Xihe：依赖外部物化能力
- MC：原生支持物化视图（MV），自动查询改写
- 高频聚合查询建议迁移为 MV

## 4.3 命名规范建议

| 类型 | 命名规范 | 示例 |
|------|---------|------|
| ODS 表 | `ods_<来源系统>_<表名>_<增量/全量>_di/fi` | `ods_mysql_order_di` |
| DWD 表 | `dwd_<数据域>_<业务过程>_<粒度>_di` | `dwd_trade_order_di` |
| DWS 表 | `dws_<数据域>_<统计周期>_<主题>_df` | `dws_trade_user_1d_df` |
| ADS 表 | `ads_<应用>_<业务描述>` | `ads_user_profile` |
| DIM 表 | `dim_<主题>_<维度描述>_df` | `dim_user_info_df` |

## 4.4 迁移要点

- [ ] 现有 Xihe 表是否使用分区，分区字段如何映射
- [ ] 长字符串字段是否需要改 STRING
- [ ] 是否引入物化视图替代部分汇总表
- [ ] 历史数据如何搬迁（一次性 + 增量）
- [ ] 主键/唯一约束在 MC 中需通过业务保证，无 PK 概念
