# 06 调度任务迁移

## 6.1 调度模型差异

| 维度 | DMS 任务编排 | DataWorks 调度 |
|------|-------------|---------------|
| 依赖机制 | 任务直接依赖 | **节点输出名（output）依赖** |
| 调度参数 | 简单变量 | 完整调度参数体系 |
| 周期 | cron 表达式 | 调度配置（分钟/小时/天/月） |
| 补数据 | 手动 | 自动化补数据流程 |
| 基线预警 | 有限 | 完整基线/SLA 体系 |
| 任务类型 | SQL 为主 | SQL/Shell/PyODPS/数据集成/虚拟节点等 |

## 6.2 依赖机制迁移

**关键差异**：DataWorks 通过 **节点输出名** 建立依赖，而非直接引用上游任务。

```
-- DataWorks 节点输出名示例
projectname.dwd_trade_order_di
```

迁移要点：
- [ ] 为每个节点规划唯一输出名（建议与表名一致）
- [ ] 下游节点通过输出名引用上游
- [ ] 跨工作空间依赖需特殊配置

## 6.3 调度参数

### 常用调度参数

| 参数 | 含义 | 示例 |
|------|------|------|
| `${bizdate}` | 业务日期（T-1） | 20260812 |
| `${bizmonth}` | 业务月 | 202608 |
| `${yyyymmdd}` | 业务日期格式 | 20260812 |
| `${tbizdate}` | 当天 | 20260813 |
| `$bizdate` | 同 ${bizdate} | 20260812 |

### 参数赋值方式
- 节点参数配置区
- 通过 `${param}` 在 SQL 中引用
- 跨节点参数传递（弱依赖）

## 6.4 调度周期与基线

- 周期：分钟/小时/天/月
- **基线**：定义任务承诺完成时间，超时告警
- 建议为核心任务配置基线，保障 SLA

## 6.5 补数据

- DataWorks 提供 **补数据** 功能，自动重跑下游链路
- 注意：补数据会触发依赖链，谨慎选择范围
- 历史分区回刷通过补数据实现
