## 二、字段说明

| 字段 | 必填 | 取值/格式 | 说明 |
|------|------|-----------|------|
| 序号 | ✅ | 3 位数字 001/002 | 唯一标识，便于引用 |
| 源库 | ✅ | 源数据库名 | 如 prd_spark_db / test_zxbs_db |
| 源表名 | ✅ | 源表名 | 不含库名前缀，不含反引号 |
| 源系统 | ✅ | MySQL / Xihe / MC | Xihe=阿里Spark引擎；MC=已是MaxCompute语法 |
| 目标库 | ✅ | MC 项目名 | 迁移后的 MaxCompute project |
| 目标表名 | ✅ | 迁移后表名 | 决定生成的 DDL/DML 文件名与表名 |
| 层级 | ✅ | ODS / DWD / DWS / ADS / DIM | 数仓分层 |
| 同步方式 | ✅ | full / incr / cdc | full=全量；incr=增量；cdc=实时 |
| 写入模式 | ✅ | OVERWRITE / INTO / MERGE | OVERWRITE=覆盖分区；INTO=追加；MERGE=主键更新 |
| 分区 | ✅ | 字段/粒度 或 - | 如 pt/d、ds/d、data_date/m；无分区填 - |
| 表类型 | ✅ | 普通 / Delta | 普通=aliorc分区表；Delta=主键表(transactional) |
| 主键 | ✅ | 字段名组合 或 - | Delta 表必填；普通表填 - |
| 负责人 | ✅ | 人名 | 该表的迁移负责人 |
| 备注 | ❌ | 自由文本 | 补充 LIFECYCLE、特殊说明、推断依据等 |

## 三、填写约定

1. **一行一表**：每个迁移表占一行，不要合并。
2. **表名不含反引号/库名前缀**：源表名和目标表名只写纯表名，库名单独放「源库/目标库」列。
3. **分区列格式固定**：`字段/粒度`，粒度用单字母 `d`(日)/`m`(月)/`y`(年)；无分区填 `-`。
4. **写入模式与表类型匹配**：
   - Delta 主键表 → 只能用 `MERGE`
   - 普通分区表 → `OVERWRITE`（推荐）或 `INTO`
   - 普通非分区表 → `INTO`（追加，不能 OVERWRITE）
5. **主键列**：Delta 表必填（如 `bill_app_no`、`project_code,contract_number`），普通表填 `-`。
6. **源系统决定迁移工作量**：
   - `MySQL` → 类型/约束/索引全改
   - `Xihe` → 函数/语法改，类型基本兼容
   - `MC` → 仅按规范补注释/调整属性
7. **新增表追加在表格末尾**，序号递增，不要插在中间打乱顺序。
8. **表名变更不要删旧行**，在备注标注「已废弃，新表见序号 XXX」。
9. **无法确认的字段**填 `<待确认>`，禁止留空或猜。

## 四、使用方式

填完映射表后，告诉我「映射表已更新」，我会：

1. 按目标表名生成对应的 DDL 脚本到 `迁移SQL脚本/01_DDL/<层级>/` 下
2. 按同步方式+写入模式生成对应的 DML 脚本到 `迁移SQL脚本/02_DML/<层级>/` 下
3. 按表名生成数据校验脚本到 `迁移SQL脚本/05_数据校验/` 下
4. 每个脚本按 `MaxCompute_SQL注释规范.md` 补全注释
