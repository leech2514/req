## 一、规范目的

1. **可读性**：通过命名即可理解表的层级、业务域、同步方式

2. **扩展性**：支持未来新增业务域和表类型

3. **唯一性**：每个表名在数仓中唯一

4. **规范性**：统一使用小写字母和下划线


### 5\.4 DWS/DM中间表

DWS/DM层在ETL过程中产生的中间计算表，用于多步骤计算的中间结果传递，非最终产出表。

```Plain Text
{分层}_{业务域}_{自定义内容}_mid_{同步方式}_{分区/事务类型}
```

示例：

```Plain Text
dws_cons_ln_account_agg_mid_incr_d          -- 消金账户汇总中间表（日分区）
dws_fin_project_subject_join_mid_incr_d     -- 财务项目科目关联中间表（日分区）
dm_cons_vintage_calc_mid_incr_m             -- 消金vintage计算中间表（月分区）
dm_fin_com_profit_step1_mid_incr_m          -- 公司利润表计算步骤1中间表（月分区）
dm_cons_cpst_vintage_pre_mid_incr_mob_m     -- 消金代偿vintage预处理中间表（MOB月分区）
```

**使用原则：**

1. 中间表仅用于ETL过程中数据传递，不对外暴露

2. 同一业务逻辑的多个中间表可通过自定义内容区分步骤（如 `_step1`、`_step2`）

3. 中间表生命周期应与对应最终表一致或更短

4. 避免在中间表上建立复杂索引，以计算性能为主

### 5\.5 CDC 增量临时表（源系统变更数据临时表）

> **CDC = Change Data Capture（变更数据捕获）**：通过时间戳字段（如 gmt\_modified）过滤源数据库当日新增/更新的数据，用于增量同步。
> 
> 

用于存储源系统当日变更数据（通过 gmt\_modified 过滤），作为 MERGE INTO 的来源表，合并到下游 Delta 事务主表。

```Plain Text
stg_{业务域}_{源表名}_incr_d
```

**典型数据流向：**

```Plain Text
源数据库（MySQL/...）
       │  WHERE gmt_modified >= 当日
       ▼
  DataWorks 数据集成任务
       │
       ▼
  stg_cons_repay_plan_incr_d       ← CDC增量临时表（日分区）
       │  字段：与源表一致 + recon_date(分区)
       ▼
  SQL 节点：MERGE INTO
       │
       ▼
  ods_cons_repay_plan_incr_delta   ← 主事务表（Delta 事务表）
       PRIMARY KEY (loan_id, plan_no, ...)
```

**示例：**

```Plain Text
stg_cons_repay_plan_incr_d        -- 消金域-还款计划-增量日分区表
stg_cons_loan_info_incr_d         -- 消金域-借据信息-增量日分区表
stg_cons_repay_flow_incr_d        -- 消金域-还款流水-增量日分区表
stg_cons_cpst_info_incr_d         -- 消金域-代偿信息-增量日分区表
stg_auto_repay_plan_incr_d        -- 车贷域-还款计划-增量日分区表
stg_fin_voucher_incr_d             -- 财务域-凭证表-增量日分区表
```

**使用说明：**

1. **表结构**：字段与源系统表一致，额外加 `recon_date` 分区字段（STRING，格式 yyyymmdd）

2. **表类型**：普通分区表（非事务），因为每天覆盖写入即可

3. **数据写入**：`INSERT OVERWRITE TABLE stg_cons_repay_plan_incr_d PARTITION(recon_date='yyyymmdd') SELECT ... FROM 源库 WHERE gmt_modified >= 当日;`

4. **下游使用**：`MERGE INTO ods_cons_repay_plan_incr_delta t USING stg_cons_repay_plan_incr_d s ON ...`

5. **生命周期**：15\~30 天（保留最近 N 天增量，方便回溯重跑，长期数据主表已保留）

## 六、字段类型规范

> **核心原则**：统一使用 MaxCompute 推荐类型，避免精度损失和兼容性问题。DECIMAL 类型使用 `DECIMAL(38,18)` 作为统一精度（阿里推荐标准，支持最大 38 位数字，小数点后保留 18 位）。
> 
> 

### 6\.1 字段类型速查表

### 6\.2 金额类字段规范

#### 6\.2\.1 统一使用 DECIMAL\(38,18\)

\-\- ✅ 推荐写法

principal\_amt     DECIMAL\(38,18\) COMMENT '本金金额',

interest\_amt      DECIMAL\(38,18\) COMMENT '利息金额',

annual\_rate       DECIMAL\(38,18\) COMMENT '年利率（如 0\.045 表示 4\.5%）',



\-\- ❌ 禁止写法

principal\_amt     DOUBLE            \-\- 二进制浮点精度丢失，SUM 后末尾出现多位垃圾

loan\_amt          FLOAT             \-\- 同上

principal\_amt     DECIMAL\(10,2\)     \-\- 精度不足，中间汇率/利率计算溢出后结果错误

#### 6\.2\.2 DECIMAL 精度选择参考

> **建议**：表存储统一用 `DECIMAL(38,18)`，查询或报表层再按需 ROUND。存储精度高不会错，存储精度低了补不回来。
> 
> 

#### 6\.2\.3 常见字段命名 \+ 类型对照

### 6\.3 日期/时间类字段规范

\-\- ✅ 推荐写法（建表字段）

`gmt_create`          TIMESTAMP COMMENT '源表创建时间',

`gmt_modified`        TIMESTAMP COMMENT '源表更新时间',

`due_date`            DATE      COMMENT '到期日',

`actual_pay_date`     DATE      COMMENT '实际还款日期',

`recon_date`          STRING    COMMENT '统计日期\(yyyymmdd\)',   \-\- 分区字段用 STRING

`dw_insert_time`      TIMESTAMP COMMENT '数仓创建时间',

`dw_update_time`      TIMESTAMP COMMENT '数仓更新时间'

### 6\.4 标识符/枚举类字段规范

### 6\.5 类型转换与注意事项

#### 6\.5\.1 DOUBLE → DECIMAL 的常见坑

\-\- ❌ 问题: DOUBLE 是二进制浮点，1\.1 在内存中实际是 1\.1000000000000000888\.\.\.

SELECT CAST\(1\.1 AS DOUBLE\) \* 100000000;  \-\- 结果可能是 109999999\.99999999，SUM 后累积误差



\-\- ✅ 正确: 一律用 DECIMAL 存储和计算

SELECT CAST\('1\.1' AS DECIMAL\(38,18\)\) \* 100000000;  \-\- 结果精确

#### 6\.5\.2 字段长度上限

DECIMAL\(38,18\): 最大支持 ±9\.999\.\.\.×10^19（足够金额/利率/汇率使用）

BIGINT:          ±9\.2 ×10^18（足够计数使用）

STRING:          最大 8 MB（足够文本使用）

#### 6\.5\.3 COUNT 结果类型

`COUNT(*)`、`COUNT(DISTINCT col)` 的返回值是 BIGINT，因此存储计数的字段请用 `BIGINT`，不要用 `DECIMAL` 或 `INT`：

\-\- ✅ 正确

loan\_cnt  BIGINT COMMENT '贷款笔数',



\-\- ❌ 错误（每次查询都需 CAST，且 INT 可能溢出大数）

loan\_cnt  INT COMMENT '贷款笔数',

loan\_cnt  DECIMAL\(38,18\) COMMENT '贷款笔数'   \-\- 非金额不要用 DECIMAL

### 7\.1 ODS\-CDC增量临时表（普通分区表）

**适用场景**：存储源系统当日变更数据（通过 gmt\_modified 过滤），作为 MERGE INTO 的来源表。

**表名格式**：stg`_{业务域}_{源表名}_incr_d`

**建表语句**：

```Plain Text
-- =================================================================
-- 表名: stg_{业务域}_{源表名}_incr_d
-- 层级: STG层（staging层，存放源系统当日CDC增量数据，生命周期短（7~30天）
-- 业务域: {业务域}
-- 同步方式: 增量（incr）
-- 分区类型: 日分区（d）
-- 表类型: 普通分区表（非事务）
-- 描述: {表中文注释}
-- 数据来源: 源数据库（MySQL/Oracle/...），通过 gmt_modified 过滤当日变更
-- 下游表: ods_{业务域}_{源表名}_incr_delta（Delta 事务表）
-- =================================================================

CREATE TABLE IF NOT EXISTS stg_{业务域}_{源表名}_incr_d(
    -- =========================================================
    -- 业务字段：与源表保持一致（按需修改）
    -- =========================================================
    `loan_id`             STRING COMMENT '借据号',
    `plan_no`             BIGINT COMMENT '期次',
    `due_date`            date COMMENT '到期日',
    `principal_amt`       DECIMAL(38,18) COMMENT '应还本金',
    `interest_amt`        DECIMAL(38,18) COMMENT '应还利息',
    `plan_status`         STRING COMMENT '还款状态',
    `actual_pay_date`     date COMMENT '实际还款日期',

    -- =========================================================
    -- 系统字段（固定保留）
    -- =========================================================
    `gmt_create`          TIMESTAMP COMMENT '源表创建时间',
    `gmt_modified`        TIMESTAMP COMMENT '源表更新时间'
)
COMMENT '{表中文注释}'
PARTITIONED BY (recon_date STRING)
LIFECYCLE 30;

-- =========================================================
-- 使用说明：
--
-- 1) 分区格式：yyyymmdd（如 20260615）
-- 2) 数据写入（DataWorks 数据集成任务或 SQL）：
--    INSERT OVERWRITE TABLE stg_{业务域}_{源表名}_incr_d
--    PARTITION (recon_date = '${bdp.system.bizdate}')
--    SELECT ... FROM 源库
--    WHERE gmt_modified >= date_format(date_sub(current_date,1),'yyyy-MM-dd');
--
-- 3) 查询方式: SELECT * FROM stg_{业务域}_{源表名}_incr_d
--               WHERE recon_date = '${bdp.system.bizdate}';
-- =========================================================
```

### 7\.2 DWD\-Delta事务表（不分区，recon\_date 作为普通字段，支持 MERGE）

**适用场景**：需要按业务主键 upsert，且同一业务主键全表唯一（不允许在多个日期重复）。如借据信息、还款计划、订单状态等会变更的明细表。

**重要**：MaxCompute 中 Delta事务表 \+ 分区时，分区字段不能出现在普通字段列表中，也不能加入主键。因此需要按主键全表唯一时，推荐**不分区**，recon\_date 作为普通字段。

**表名格式**：`dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta`

**建表语句**：

```Plain Text
-- =================================================================
-- 表名: dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta
-- 层级: DWD层（明细数据层）
-- 业务域: {业务域}
-- 同步方式: 增量（incr）
-- 表类型: Delta事务表（不分区）
-- 描述: {表中文注释}
-- 主键: 业务主键（不含 recon_date，确保全表唯一）
-- 上游表: ods_{业务域}_{源表名}_incr_d
-- =================================================================

CREATE TABLE IF NOT EXISTS dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta(
    -- =========================================================
    -- 日期字段（普通字段，可被 UPDATE）
    -- =========================================================
    `recon_date`          STRING NOT NULL COMMENT '统计日期(yyyymmdd)',

    -- =========================================================
    -- 主键字段（必填，全表唯一）
    -- =========================================================
    `loan_id`             STRING NOT NULL COMMENT '借据号',
    `plan_no`             BIGINT NOT NULL COMMENT '期次',

    -- =========================================================
    -- 业务字段
    -- =========================================================
    `due_date`            date COMMENT '到期日',
    `principal_amt`       DECIMAL(38,18) COMMENT '应还本金',
    `interest_amt`        DECIMAL(38,18) COMMENT '应还利息',
    `plan_status`         STRING COMMENT '还款状态',
    `actual_pay_date`     date COMMENT '实际还款日期',

    -- =========================================================
    -- 数仓系统字段
    -- =========================================================
    `dw_insert_time`      TIMESTAMP COMMENT '数仓创建时间',
    `dw_update_time`      TIMESTAMP COMMENT '数仓更新时间',
    PRIMARY KEY (loan_id, plan_no)
)
COMMENT '{表中文注释}'
TBLPROPERTIES (
    "transactional"="true",
    "write.bucket.num"="16"
)
LIFECYCLE 365;

-- =========================================================
-- 使用说明：
--
-- 1) 增量更新（MERGE INTO，推荐）：
--    MERGE INTO dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta t
--    USING (
--        SELECT * FROM ods_{业务域}_{源表名}_incr_d
--        WHERE recon_date = '${bdp.system.bizdate}'
--    ) s
--    ON  t.loan_id = s.loan_id
--    AND t.plan_no = s.plan_no
--    WHEN MATCHED THEN UPDATE SET
--        t.recon_date      = '${bdp.system.bizdate}',  -- 更新日期
--        t.due_date        = s.due_date,
--        t.principal_amt   = s.principal_amt,
--        t.interest_amt    = s.interest_amt,
--        t.plan_status      = s.plan_status,
--        t.actual_pay_date = s.actual_pay_date,
--        t.dw_update_time  = current_timestamp()
--    WHEN NOT MATCHED THEN INSERT (
--        recon_date, loan_id, plan_no, due_date, principal_amt,
--        interest_amt, plan_status, actual_pay_date,
--        dw_insert_time, dw_update_time
--    ) VALUES (
--        '${bdp.system.bizdate}', s.loan_id, s.plan_no, s.due_date, s.principal_amt,
--        s.interest_amt, s.plan_status, s.actual_pay_date,
--        current_timestamp(), current_timestamp()
--    );
--
-- 2) 查询（按日期过滤）：
--    SELECT * FROM dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta
--    WHERE recon_date = '20260615';
--
-- 3) 关键注意事项：
--    - recon_date 是普通字段，不是分区字段，可以被 UPDATE
--    - 主键 (loan_id, plan_no) 全表唯一，不允许同一借据在多条记录中出现
--    - 没有分区裁剪，依赖 WHERE recon_date 过滤
-- =========================================================
```

### 7\.2\.1 Delta事务表 \+ 分区（谨慎使用，适用于按天快照场景）

**适用场景**：需要保留每日快照，同一天内按业务主键唯一，但不同日期可以有不同版本。

**重要**：分区字段不能出现在普通字段列表中，也不能加入 PRIMARY KEY。主键只包含业务字段，因此同一业务主键在不同分区是独立的。

**表名格式**：`dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta`

**建表语句**：

```Plain Text
-- =================================================================
-- 表名: dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta
-- 层级: DWD层（明细数据层）
-- 业务域: {业务域}
-- 同步方式: 增量（incr）
-- 表类型: Delta事务表 + 分区
-- 描述: {表中文注释}（按日快照，每天可独立 upsert）
-- 主键: 业务主键（不含分区字段，分区内唯一，跨分区可重复）
-- 上游表: ods_{业务域}_{源表名}_incr_d
-- =================================================================

CREATE TABLE IF NOT EXISTS dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta(
    -- =========================================================
    -- 主键字段（必填，分区内唯一）
    -- =========================================================
    `loan_id`             STRING NOT NULL COMMENT '借据号',
    `plan_no`             BIGINT NOT NULL COMMENT '期次',

    -- =========================================================
    -- 业务字段
    -- =========================================================
    `due_date`            date COMMENT '到期日',
    `principal_amt`       DECIMAL(38,18) COMMENT '应还本金',
    `plan_status`         STRING COMMENT '还款状态',

    -- =========================================================
    -- 数仓系统字段
    -- =========================================================
    `dw_insert_time`      TIMESTAMP COMMENT '数仓创建时间',
    `dw_update_time`      TIMESTAMP COMMENT '数仓更新时间',
    PRIMARY KEY (loan_id, plan_no)
)
COMMENT '{表中文注释}（按日快照）'
PARTITIONED BY (recon_date STRING)
TBLPROPERTIES (
    "transactional"="true",
    "write.bucket.num"="16"
)
LIFECYCLE 365;

-- =========================================================
-- 使用说明：
--
-- 1) INSERT OVERWRITE 覆盖分区（整分区重算）：
--    INSERT OVERWRITE TABLE dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta
--    PARTITION (recon_date = '${bdp.system.bizdate}')
--    SELECT loan_id, plan_no, ... FROM ...;
--
-- 2) MERGE INTO 指定分区（增量更新）：
--    MERGE INTO dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta t
--    USING (
--        SELECT * FROM ods_{业务域}_{源表名}_incr_d
--        WHERE recon_date = '${bdp.system.bizdate}'
--    ) s
--    ON  t.loan_id = s.loan_id
--    AND t.plan_no = s.plan_no
--    WHEN MATCHED THEN UPDATE SET ..., t.dw_update_time = current_timestamp()
--    WHEN NOT MATCHED THEN INSERT (...) VALUES (...);
--
-- 3) 查询（分区裁剪生效）：
--    SELECT * FROM dwd_{业务域}_{业务过程}_{自定义内容}_incr_delta
--    WHERE recon_date = '20260615';
--
-- 4) 注意：同一借据在不同日期分区可各有一份数据（如每日快照场景）。
--    如果不需要每日快照，希望全表唯一，使用 8.2 节"不分区"方案。
-- =========================================================
```

### 7\.10 表类型选择指南

**Delta事务表 vs 普通分区表决策指南**：

```Plain Text
┌─ 需要按业务主键 upsert 更新吗？ ──┐
│                                  │
│   是 ──┐                         │   否 ──┐
│        │                         │         │
│        ▼                         │         ▼
│   同一业务主键需要全表唯一吗？    │   每天独立计算
│   │                               │   使用普通分区表 *_incr_d
│   │                               │   INSERT OVERWRITE
│   是 ──┐                   否 ──┐
│   │                         │
│   ▼                         ▼
│   Delta事务表（不分区）     Delta事务表 + 分区
│   dwd_*_incr_delta         dwd_*_incr_delta
│   recon_date 是普通字段      recon_date 是分区字段
│   MERGE INTO 更新            每日快照，MERGE 或 OVERWRITE
│   全表唯一                   分区内唯一
└──────────────────────────────────┘
```

**Delta事务表分区字段的重要约束**：

- 分区字段（如 recon\_date）**不能**出现在普通字段列表中

- 分区字段**不能**加入 PRIMARY KEY

- 因此 Delta\+分区表中分区字段无法被 UPDATE，数据创建后所在分区固定

- 如果需要每天更新分区字段，使用"不分区"方案，recon\_date 作为普通字段

## 八、源系统→ODS 增量同步数据开发规范

### 8\.1 适用场景

源系统变更数据 CDC（Change Data Capture）同步流程：

```Plain Text
源系统变更数据 → DataWorks数据集成任务 → stg 当日增量临时表（pt=yyyymmdd）
                                          → SQL节点 → ods Delta事务表（按业务主键 upsert）
```

**数据流特点**：

- stg 增量临时表中 `recon_date`（源表更新日期）可能包含多个不同日期

- 需要将各日期数据分别合并到 ods 对应分区

- 同一业务主键的数据，取最新值覆盖

**命名参考（分区/事务类型标识）**：

- `_incr_d` = 增量写入，普通分区表（stg 临时表用）

- `_incr_delta` = 增量写入，Delta 事务表（ods 主表用）

---

### 8\.2 分层与方案选择决策表

---

### 8\.3 stg层：当日增量临时表建表规范（普通分区表 \_incr\_d）

**适用条件**：staging 层临时表，存放当日 CDC 增量数据，生命周期短（通常 7\~30 天）

**建表模板**：

```Plain Text
-- ============================================================================
-- 表名: stg_{业务域}_{业务过程}_incr_d
-- 类型: 普通分区表（STORED AS aliorc，非事务）
-- 分区字段: pt STRING（格式 yyyymmdd）
-- 生命周期: LIFECYCLE 30
-- 说明: 源系统CDC变更数据的当日落地临时表
-- ============================================================================

CREATE TABLE IF NOT EXISTS stg_{业务域}_{业务过程}_incr_d (
    data_source       STRING        COMMENT '数据来源（源系统标识）',
    recon_date        DATE          COMMENT '源表更新日期',
    {业务字段1}       {类型}        COMMENT '{业务注释}',
    {业务字段2}       {类型}        COMMENT '{业务注释}',
    ... ... ... ... ... ... ... ... ,
    dw_insert_time    TIMESTAMP     COMMENT '数仓创建时间',
    dw_update_time    TIMESTAMP     COMMENT '数仓更新时间'
)
COMMENT 'stg层-{业务域}-{业务过程}-当日CDC增量临时表'
PARTITIONED BY (pt STRING)         -- 分区字段: pt = yyyymmdd
STORED AS aliorc
LIFECYCLE 30;                      -- 临时表生命周期30天
```

**数据写入方式**：DataWorks 数据集成任务 → `INSERT OVERWRITE TABLE stg_xxx_incr_d PARTITION(pt='${bdp.system.bizdate}')`

**字段映射原则**：

- `data_source`：标识源系统（如 `CORE_DB`、`FINANCE_DB`）

- `recon_date`：源表的更新日期字段（如 source\_update\_date），用于决定目标分区

- 业务字段：与源表保持一致（字段名建议统一小写，命名遵循业务语义）

- `dw_insert_time` / `dw_update_time`：落地时统一设置为 `CURRENT_TIMESTAMP()`

- `pt`：分区字段，不在普通字段列表中，值 = `TO_CHAR(recon_date, 'yyyymmdd')`

### 8\.4 ods层 \- 方案A：普通分区表建表 \+ INSERT OVERWRITE 增量合并（\_incr\_d）

**适用条件**：ODS 层主表，普通分区表（非事务），通过 `INSERT OVERWRITE + UNION ALL + ROW_NUMBER()` 实现"按主键取最新"的效果

**适用场景**：

- 分区内数据量不大（或更新比例较大）

- 对写入性能敏感，SLA 紧张

- 不需要保留 `dw_insert_time` 等精细元数据

- 新团队/新项目初期，希望降低复杂度

**核心逻辑**：ODS 旧数据 `UNION ALL` STG 新数据 → 按 `(业务主键, recon_date)` 用 `ROW_NUMBER()` 去重 → `INSERT OVERWRITE` 覆盖回 ODS 分区

**建表模板**：

```Plain Text
-- ============================================================================
-- 表名: ods_{业务域}_{业务过程}_incr_d
-- 类型: 普通分区表（STORED AS aliorc，非事务）
-- 分区字段: pt STRING（格式 yyyymmdd）
-- 说明: ODS层主表，按主键取最新，整分区覆盖写入
-- ============================================================================

CREATE TABLE IF NOT EXISTS ods_{业务域}_{业务过程}_incr_d (
    data_source       STRING        COMMENT '数据来源（源系统标识）',
    recon_date        DATE          COMMENT '源表更新日期',
    {业务字段1}       {类型}        COMMENT '{业务注释}',
    {业务字段2}       {类型}        COMMENT '{业务注释}',
    ... ... ... ... ... ... ... ... ,
    dw_insert_time    TIMESTAMP     COMMENT '数仓创建时间',
    dw_update_time    TIMESTAMP     COMMENT '数仓更新时间'
)
COMMENT 'ods层-{业务域}-{业务过程}-增量合并表（普通分区表）'
PARTITIONED BY (pt STRING)         -- 分区字段: pt = yyyymmdd
STORED AS aliorc
TBLPROPERTIES ("columnar.nested.type"="true");
```

**INSERT OVERWRITE 增量合并模板**：

```Plain Text
-- ============================================================================
-- DataWorks 任务名称: ods_{业务域}_{业务过程}_incr_d_write
-- 任务类型: SQL节点
-- 上游依赖: stg_{业务域}_{业务过程}_incr_d_write
-- 调度周期: 每日
-- 变量: ${bdp.system.bizdate} = 前一天日期，格式 yyyymmdd
-- ============================================================================

set odps.dynamic.partition.mode=nonstrict;
set odps.sql.allow.dynamic.partition=true;

INSERT OVERWRITE TABLE dev_dw_01.ods_{业务域}_{业务过程}_incr_d
PARTITION (pt)

SELECT
    data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
    dw_insert_time, dw_update_time,
    TO_CHAR(recon_date, 'yyyymmdd')   -- 最后一列 = pt 分区值
FROM (
    -- ============================================================
    -- 合并 ODS 旧数据 + STG 新数据，按 (业务主键, recon_date) 去重
    -- ROW_NUMBER() = 1 即"主键相同取 dw_update_time 最新的一条"
    -- ============================================================
    SELECT
        data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
        dw_insert_time, dw_update_time,
        ROW_NUMBER() OVER (PARTITION BY {业务主键字段}, recon_date
                           ORDER BY dw_update_time DESC) AS rn
    FROM (
        -- =====================================================
        -- 数据源 1: ODS 原有数据（只读取 STG 中存在的 recon_date 对应分区）
        -- =====================================================
        SELECT
            data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
            dw_insert_time, dw_update_time
        FROM dev_dw_01.ods_{业务域}_{业务过程}_incr_d
        WHERE pt IN (
            SELECT DISTINCT TO_CHAR(recon_date, 'yyyymmdd')
            FROM dev_dw_01.stg_{业务域}_{业务过程}_incr_d
            WHERE pt = '${bdp.system.bizdate}'
        )

        UNION ALL

        -- =====================================================
        -- 数据源 2: STG 当日增量数据
        -- dw_update_time = CURRENT_TIMESTAMP() → 作为最新数据
        -- =====================================================
        SELECT
            data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
            CURRENT_TIMESTAMP() AS dw_insert_time,
            CURRENT_TIMESTAMP() AS dw_update_time
        FROM dev_dw_01.stg_{业务域}_{业务过程}_incr_d
        WHERE pt = '${bdp.system.bizdate}'
    ) combined_data
) ranked
WHERE rn = 1;   -- 主键相同取 dw_update_time 最新的一条
```

**执行效果**：

**普通分区表 INSERT OVERWRITE 的 3 条规则**：

1. ✅ 使用 `PARTITION (pt)` 动态分区，不能写 `PARTITION (pt = TO_CHAR(...))`

2. ✅ `SELECT` 最后一列 = `TO_CHAR(recon_date, 'yyyymmdd')` 作为 pt 分区值

3. ✅ 通过 `WHERE pt IN (SELECT DISTINCT TO_CHAR(recon_date, 'yyyymmdd') FROM stg)` 只读取受影响的分区，避免全表扫描

### 8\.5 ods层 \- 方案B：Delta事务表建表 \+ MERGE INTO 增量同步（\_incr\_delta）

**适用条件**：ODS 层主表，Delta 事务表（`transactional=true`），支持按主键 upsert

**适用场景**：

- 需要真正按行 upsert（每天只更新一部分行）

- 数据量大但每日变更比例小

- 需要保留 `dw_insert_time` 等原始元数据（不能整分区覆盖）

- 有审计/合规要求（需要知道"这条数据哪天被谁更新过"）

- 需要版本回滚能力

**核心逻辑**：stg 当日增量 → 按 `(业务主键, recon_date)` 匹配 ods 表 → 命中则 UPDATE，未命中则 INSERT

**建表模板**：

```Plain Text
-- ============================================================================
-- 表名: ods_{业务域}_{业务过程}_incr_delta
-- 类型: Delta事务分区表（支持 MERGE INTO / UPDATE / DELETE）
-- 分区字段: pt STRING（格式 yyyymmdd）
-- 说明: ODS层主表，按业务主键 upsert，保留完整历史数据
-- ============================================================================

CREATE TABLE IF NOT EXISTS ods_{业务域}_{业务过程}_incr_delta (
    data_source       STRING        COMMENT '数据来源（源系统标识）',
    recon_date        DATE          COMMENT '源表更新日期',
    {业务字段1}       {类型}        COMMENT '{业务注释}',
    {业务字段2}       {类型}        COMMENT '{业务注释}',
    ... ... ... ... ... ... ... ... ,
    dw_insert_time    TIMESTAMP     COMMENT '数仓创建时间',
    dw_update_time    TIMESTAMP     COMMENT '数仓更新时间'
)
COMMENT 'ods层-{业务域}-{业务过程}-增量事务表'
PARTITIONED BY (pt STRING)                     -- 分区字段: pt = yyyymmdd
STORED AS aliorc
TBLPROPERTIES (
    "transactional"="true",                    -- Delta事务表标识 ✅
    "comment"="按业务主键upsert的ODS增量表"
);
```

**MERGE INTO 增量同步模板**：

```SQL
-- ============================================================================
-- DataWorks 任务名称: ods_{业务域}_{业务过程}_incr_delta_merge
-- 任务类型: SQL节点
-- 上游依赖: stg_{业务域}_{业务过程}_incr_d_write
-- 调度周期: 每日
-- 变量: ${bdp.system.bizdate} = 前一天日期，格式 yyyymmdd
-- ============================================================================

MERGE INTO dev_dw_01.ods_{业务域}_{业务过程}_incr_delta t

USING (
    -- stg当日增量数据
    SELECT
        data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
        dw_insert_time, dw_update_time,
        TO_CHAR(recon_date, 'yyyymmdd') AS pt_value   -- 生成目标分区值
    FROM dev_dw_01.stg_{业务域}_{业务过程}_incr_d
    WHERE pt = '${bdp.system.bizdate}'
) s

-- 匹配条件: 业务主键 + recon_date
-- pt 是分区字段，不能出现在 ON 条件中
ON t.{业务主键字段} = s.{业务主键字段}
AND t.recon_date = s.recon_date

WHEN MATCHED THEN UPDATE SET
    t.data_source = s.data_source,
    t.{业务字段1} = s.{业务字段1},
    t.{业务字段2} = s.{业务字段2},
    ... ... ... ... ... ,
    t.dw_update_time = CURRENT_TIMESTAMP()   -- 匹配时更新更新时间

WHEN NOT MATCHED THEN INSERT (
    data_source, recon_date, {业务字段1}, {业务字段2}, ... ,
    dw_insert_time, dw_update_time, pt
) VALUES (
    s.data_source, s.recon_date, s.{业务字段1}, s.{业务字段2}, ... ,
    CURRENT_TIMESTAMP(),                      -- 新增时设置创建时间
    CURRENT_TIMESTAMP(),                      -- 新增时设置更新时间
    s.pt_value                                -- 分区字段值放在 VALUES 最后一列
);
```

**执行效果**：

**Delta 事务表 MERGE INTO 的 3 条规则**：

1. ✅ 分区字段 `pt` **不能出现在 ON 匹配条件**中

2. ✅ 分区字段 `pt` **不能被 UPDATE**（UPDATE SET 列表中不能出现 `pt`）

3. ✅ 分区字段 `pt` 在 INSERT 时放在**字段列表最后一列**，VALUES 中也放在最后

### 8\.8 决策指南（什么时候选方案A，什么时候选方案B）

> **核心原则**：MERGE INTO 的强大能力不是免费的，需根据更新模式决定是否值得付出代价。
> 
> 

**✅ 选方案B（Delta事务表 \+ MERGE INTO）**：

1. 需要真正**按行 upsert**（如客户画像、产品主数据，每天只更新一部分）

2. 数据量大但**每日变更比例小**（100 万行表，每天只变 5%）

3. 需要**保留** **`dw_insert_time`** **等原始元数据**（不能整分区覆盖）

4. **审计/合规要求**（需要知道"这条数据哪天被谁更新过"）

5. **需要版本回滚能力**（随时能"回到昨天的数据状态"）

**✅ 选方案A（普通分区表 \+ INSERT OVERWRITE）**：

1. 分区内数据量不大但**分区数很多**

2. **对写入性能敏感**（SLA 紧张、希望越快越好）

3. **不需要保留 dw\_insert\_time 精细元数据**（每次合并更新都可以）

4. **历史数据不再改动**（T\+1 数据一旦确定就不会再变）

5. **新团队/新项目初期**（降低复杂度，先跑通再优化）

#### 一句话总结

> **方案A INSERT OVERWRITE：简单可靠、快，但每次必须重算受影响的分区，不能保留 dw\_insert\_time 元数据。**
> 
> **方案B MERGE INTO：精确、优雅、保留元数据，但更慢、更复杂、有存储和版本管理成本。**
> 
> 选择依据：你的更新模式是否真的需要"行级 upsert \+ 元数据保留"。如果每天都是全量重算指标，方案A更合适；如果是逐条更新主数据，方案B才值得付出这些代价。
> 
>
